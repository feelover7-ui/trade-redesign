# v0.9 OZD 내부 직접 변환 — 외부 OZ 프로그램 불필요

## 이번 변경

v0.8은 OZ SDK를 별도로 요구했다. **v0.9의 기본 업로드 경로는 SDK/브릿지/브라우저/AI를 사용하지 않는다.** `server/ozd/native.mjs`가 지원 OZD의 저장된 소요조회 데이터 구조를 읽어 표준 XLSX를 만들고, 기존 엑셀 검증·등록 과정으로 연결한다. 별도의 API키·OZ프로그램·HTML5라이선스·Chrome 설치는 이 직접 변환에 필요 없다.

사용 흐름: 물품 올리기 → OZD 드래그 → **OZD 직접 변환 완료**와 행수/수량 확인 → 변환 엑셀 받기(선택) → 등록 전 검증·미리보기 → 비공개 초안 등록 → 기존 조달청 API로 제품정보 보완 → 현물/증빙/독립 검토 후 게시.

이미 보관한 변환 대기 파일은 파일 업로드 이력에서 열고 **직접 변환 다시 시도**를 누른다. 원본을 다시 제출할 필요가 없다. 지원되는 파일은 기존 브릿지 설정이 있더라도 네이티브 변환이 먼저 성공하며 외부 변환 호출은 없다.

## 지원 범위 (모든 OZD 변환기가 아님)

- 비밀번호 표시가 `NoPassword_Entered`인 OZP **3.0.0.1** 포장 형식.
- 저장된 `OZBINDEDDATAMODULE` version **2040**, `ByteArraySet` 소요조회 표.
- 물품명 `THNG_NM`, 등록수량 `REQRE_INQIRE_QTY`, 분류번호 `THNG_CL_CD`, 식별번호 `THNG_IDNTFC_CD`가 있는 단일 표.
- 관찰·검증한 셀 형식: 문자열(12), 문자로 직렬화된 수치(2). 1~2,000행/입력8MB 이하.
- 출력 열: G2B목록번호, G2B목록명, 등록수량, 취득일자, 취득단가, 물품상태, 신청수량, 물품분류번호, 물품식별번호.

**미지원:** 비밀번호 문서, 다른 OZP/데이터 버전·다른 셀 형식, 데이터가 없는 이미지형 보고서, 여러 물품 데이터셋, 손상된 인덱스·압축. 일부 행만 성공한 것처럼 누락시키지 않고 원본을 보관한 채 이유를 표시한다. 보고서의 인쇄 레이아웃·사진·스크립트·수식에 의한 표시값을 재현하는 기능은 아니다. 저장된 원시 물품 데이터를 옮긴다. 렌더링 시 계산되거나 손으로 수정한 보고서 표시와 원시값이 다른 파일은 별도 대조해야 한다.

## 데이터 보존과 보안

물품번호 앞자리0, 행별 수량·취득일·취득단가·폐품 상태를 보존한다. 반복 번호의 서로 다른 행은 원래대로 남긴다. 임의 자산번호·품명·양호 상태·불용승인·게시를 만들지 않는다. 가용 수량과 양호 여부는 기존 업무 검수로 확정한다.

원본 BLOB/SHA-256은 기존 `import_documents`에 보관한다. 추가 schema5 테이블 `import_document_exports`에 생성된 XLSX 및 SHA-256만 저장한다. 로그인한 소속기관 업무 담당자만 `GET /api/imports/:id/export.xlsx`로 내려받는다. 원본/변환 해시 불일치는 다운로드를 차단한다. 시스템관리자·다른기관에는 파일을 공개하지 않는다.

worker_threads 격리/12초 시간제한/메모리 제한, 디렉터리 경계·중복·겹침·gzip CRC·압축팽창·행 인덱스·필드 길이·인코딩·전체 소비 길이를 검증한다. 문서 내부 JS·XML 스크립트·실행코드·외부 주소를 실행/호출하지 않는다. 문서 안 파일명은 디스크 경로로 쓰지 않는다. 엑셀 문자셀에는 수식이 생성되지 않는다.

## 선택적 로컬 명령

```powershell
npm run ozd:convert -- "C:\자료\소요조회등록.ozd" --output "C:\자료\소요조회등록_변환.xlsx"
```

Node24와 기존 의존성만 필요하다. `--output`은 새 파일이어야 하며 기존 파일을 덮어쓰지 않는다. 웹 사용자는 이 명령을 직접 실행할 필요 없다.

## 실제 파일 검증과 한계

공개 교육청 게시물의 소요조회 OZD **1개(13,256바이트)**를 다운로드해 별도 OZ 프로그램 없이 변환했다. 15행·총165개, 출력9열의135개 셀이 독립 Python 판독 원시값과 일치했다. 입력 SHA-256은 `59f578d4edf721b0a92f213371430c9e41e5932086b94086f60ca3b2321de041`이다. 검증 메타데이터만 `docs/evidence/native-ozd-public-summary.json`에 보관했다. 원본 공공 문서나 전용 뷰어 라이브러리는 저장소에 복사하지 않았다.

공개 출처: https://open.gwe.go.kr/main/bbs/view.do?bbsSn=29593&key=m2307210722956

사용자가 이 대화에 첨부한 **13,505바이트 OZD와 20행 엑셀은 이번 실행환경에서 바이트를 읽는 도구가 실패해 직접 대조하지 못했다.** 위 실검증은 공개 샘플의 결과이며 사용자 파일 검증으로 바꿔 보고하지 않는다. 사용자 파일은 Codex의 로컬에서 같은 경로로 검수한다. 다른 형식이면 코드를 무조건 성공 처리하지 말고 실패 코드·버전과 필요한 샘플 구조를 확인한다.

## 기존 브릿지의 위치

`tools/ozd-bridge/`는 이전 버전과의 호환을 위해 남았다. 기본 직접 변환에는 사용하지 않는다. 예외적으로 별도의 허가된 환경에서만 `OZD_LEGACY_BRIDGE_FALLBACK=true`를 지정할 수 있다. 기본값 false이며 사용자 요구에 맞춰 활성화할 필요가 없다. 암호·손상 오류를 이 옵션으로 우회하지 않는다. 기존 DeepSeek/조달청 키는 변경하지 않는다.

## 저작자 표시

PC1 (Pukall Cipher 1) 알고리즘: **(c) Alexandre Pukall, 1991**. 독립 구현이며 원저작자 표시를 이 문서·코드·CLI 도움말·앱 ‘연결·설정 → 프로그램 구성·저작자 표시’에 포함했다. 저작자는 알고리즘 사용/수정을 허용하되 문서와 소프트웨어 내 접근 가능한 저작자 표시를 요구했다. 원문: https://mailing-list-archive.cryptoanarchy.wiki/archive/1997/04/ffbc171d5bcf04f973e9d17ba95407bea6b0cae3a01dd13f5fe5fda9d60e618a/

제조사의 브라우저 런타임 코드는 포함하거나 실행하지 않는다. 공개 샘플의 파일 구조와 표준 PC1 알고리즘을 대상으로 데이터 변환 코드를 새로 작성했다. 비밀번호 복구·라이선스 해제 기능이 아니다.
