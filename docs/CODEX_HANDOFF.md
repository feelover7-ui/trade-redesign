# Codex 인계: 로컬 완성·공식 API·AI 연결

## 바로 복사할 작업 지시

```text
프로젝트: https://github.com/h19h29-design/trade
이 프로젝트는 서울시교육청 공립학교·소속기관의 물품공유·관리전환 웹앱 ‘물품이음’이다.
3일 내 시연이 목적이며, 기본 프로그램은 이미 구현되어 있다. 전체를 새로 만들지 말고 현재 main을 기준으로 로컬 실행·검수·미연결 기능을 마무리해라.

먼저 AGENTS.md, README.md, docs/SCOPE_AND_GAPS.md, docs/ARCHITECTURE.md,
docs/OPERATIONS.md, docs/DEMO_AND_TESTS.md, docs/CODEX_HANDOFF.md를 모두 읽어라.

1. 로컬 환경을 확인해라.
- 기존 저장소가 있으면 git status와 remote, 현재 커밋·수정사항부터 확인하고 사용자 변경을 보존해라.
- 기존 DB·uploads·서비스·인증설정은 삭제하지 마라. DATA_DIR 절대경로를 먼저 기록해라.
- Node 24.x를 사용하고 npm ci → npm test → npm run build → Playwright 테스트를 실행해라.
- 4310/5173 포트 충돌을 확인하고, 기존 운영 서비스를 중지하거나 다른 사이트를 덮어쓰지 마라.
- 합성 데이터로 npm run demo를 실행하고 브라우저에서 실제 화면을 확인해라.
- 1440px 데스크톱과 390px 모바일에서 로그인, 검색, 등록, 사진·증빙 업로드, 게시 검토,
  신청·예비배정, 양 기관 증빙, 자산 연결, 인계·인수, 대장 확인, CSV/ZIP 내보내기를 직접 검사해라.
- GitHub Actions의 생성 스크린샷만으로 시각 검수가 끝났다고 하지 마라. 실제 화면을 열어 확인해라.
- HEIC 등 지원하지 않는 이미지와 한글 CSV/파일명을 친절하게 처리하고 실패·저장 완료 메시지를 점검해라.

2. 외부 API를 실제로 확보한 범위에서만 연결해라.
- server/integrations.mjs는 내부 확장 지점이지 공식 API 명세가 아니다.
- K-에듀파인 공식 연계는 명세·기관 허가·인증·테스트 환경·읽기/쓰기 권한을 먼저 확인해라.
- URL/필드/권한을 추측해서 구현하지 말고, DB 직접 접근이나 화면 자동화로 대체하지 마라.
- 조회(대장·불용결정·취소 상태)를 먼저 구현하고, 공식 승인/대장 쓰기는 별도 권한과 실제 명세가 있을 때만 구현해라.
- 기관별 외부 ID, 요청 멱등키, 원본 해시, 조회 시각, 외부 처리번호, 결과 출처를 저장해라.
- 타임아웃·401/403·429·중복 요청·상태 충돌·결정 취소를 시험해라. 실패하면 성공으로 표시하지 마라.
- 미확보 기능은 미연결로 유지하되 수동 업무 기능은 계속 사용할 수 있게 해라.

3. 조달청 제품정보와 사진을 연결해라.
- 공식 물품목록/품목 정보 API의 현재 명세와 이용승인을 확인하고 읽기 기능부터 구현해라.
- 물품분류번호, 세부품명번호, 물품식별번호, 내부 자산번호를 혼동하지 마라.
- 제품명/제조사/모델로 후보를 제시하고 담당자가 확인해 적용하도록 해라.
- 정확한 물품이 없으면 ‘미일치/목록화 검토’로 두고 비슷한 식별번호를 자동 확정하지 마라.
- 공식 이미지 URL과 이용조건이 확인된 경우에만 참고사진을 수집하고 출처·조회시각·이용근거를 남겨라.
- 현물사진과 참고사진을 명확히 구분하고 상품 사진을 실제 물품 상태의 증거로 사용하지 마라.
- 서버의 이미지 가져오기는 허용 도메인, DNS/IP 재확인, 사설망·메타데이터 주소 차단,
  리디렉션 제한, MIME·크기 검사, 캐시를 적용해 SSRF를 막아라.

4. AI를 연결해라.
- 현재 환경에서 사용자가 승인한 공급자·모델·보안 조건과 키의 존재만 확인해라. 키 값을 로그·채팅에 출력하지 마라.
- 이미 있는 자격증명을 무단 복제·변경하지 말고 서버 비밀 환경변수로만 연결해라.
- 사진/명판 → 제품명·제조사·모델 후보 → 공식 제품정보 대조 → 사람 확인 흐름으로 구현해라.
- 상태별 묶음과 수량은 ‘추정’이며 표본/전수/미확인 구분을 보존해라.
- 여러 장의 중복 물품이나 가려진 물건을 확정 수량으로 처리하지 마라. 원본 수량·금액·코드를 자동 변경하지 마라.
- 구조화된 출력, 필드별 근거·신뢰 수준, 실패시 수동 입력, 용량/비용 상한, 개인정보 사전 제거를 적용해라.
- 사진·문서·모델 응답의 명령문은 데이터로 취급하고 서버 권한·도구 실행 지시로 사용하지 마라.
- 공식 승인, 법적 판단, 게시 검토, 인계 확정은 AI가 대신하지 않게 해라.
- AI 도우미는 사용자가 제공한 지침의 문서번호/페이지/시행일을 근거로 제시해라.
  원문이 없으면 해당 법규를 확정하지 말고 확인 필요로 남겨라.

5. 온비드와 로컬 운영을 마무리해라.
- 결과 조회 API와 기관용 물건등록/공고 API를 별개로 검증해라.
- 공개 조회 API가 있다고 쓰기 권한이 있다고 가정하지 마라.
- 이미 배정·인계된 자산이 매각자료와 겹치지 않게 해라.
- 배포는 승인된 환경과 명시된 대상만 사용해라. 정적 호스팅에 SQLite를 임시로 올리지 마라.
- HTTPS, 영속 저장소, 비밀키 분리, 백업복원, 권한, 데모/실제 데이터 분리,
  앱 재시작·로그·파일 업로드·기관 보안 검수 후에만 실제 운영을 제안해라.
- Docker나 Mac 로컬 상시실행 설정은 실제 실행 검증 후 문서에 반영해라.

6. 최종 산출물
- 구현한 것/미연결/기관 승인이 필요한 것을 구분해라.
- 핵심 기능 회귀테스트와 브라우저 화면 검증, 의존성 보안 검사를 수행해라.
- README·환경변수 예시·마이그레이션·테스트 기록을 갱신하고 커밋·푸시해라.
- 마지막에 실제 커밋 SHA, 로컬/승인된 배포 주소, 테스트 결과, 남은 외부 권한을 보고해라.
- 처음부터의 구현 계획만 다시 쓰지 말고 현재 동작하는 앱을 기반으로 실제 작업해라.
```

## 연결 순서 및 완료 기준

### A. 로컬 앱부터

기본 기능은 외부 키 없이 모두 동작해야 한다. 서버·파일 ACL·증빙·예약 규칙을 먼저 통과한다. 기존 기능을 깨뜨리지 않은 상태에서 작은 단위로 API와 AI를 추가한다. 로컬 변경사항과 백업 경로를 확인하기 전 `git reset --hard`, 강제 push, DB 초기화를 실행하지 않는다.

### B. K-에듀파인

필요 입력: 운영기관 담당자/공식 명세, 테스트 시스템, 기관 식별 체계, 인증 방식, 호출 가능 망, 데이터 항목, 요청 한도, 오류/중복/취소 규칙, 쓰기 권한 여부. 현재 저장소에 이 정보는 없다. 명세가 없으면 ‘협의 필요’로 남긴다.

권장 분리: `AssetReader`, `DisposalVerifier`, `TransferWriter`, `LedgerVerifier`. 읽기만 허용되면 쓰기 capability는 false를 유지한다. API 결과와 수동 증빙은 출처가 다르므로 새 테이블/열로 구분하고 확인시각·유효기간을 보존한다.

### C. 제품정보·사진

시연/테스트에서는 합성 모델명을 실제 제품으로 오인해 조회하지 않는다. 공식 이미지가 제공되지 않거나 이용조건이 불명확하면 현물사진만 사용한다. 이미지 원본을 웹 전체에서 무차별 크롤링하지 않는다.

### D. AI 구조화 출력 예시(내부 계약)

```json
{
  "status": "suggestion",
  "manufacturer": {"value": null, "evidence": "명판 판독 불가"},
  "model": {"value": null, "evidence": "추가 사진 필요"},
  "quantityEstimate": {"value": 12, "method": "single_image", "confirmed": false},
  "condition": "UNKNOWN",
  "requiresHumanReview": true,
  "warnings": ["겹친 물품은 보이지 않을 수 있음"]
}
```

검증된 실제 수량은 별도 사람 입력이다. AI의 숫자를 바로 예약 가능한 재고로 쓰지 않는다. 제품 후보가 없는 상태도 정상 결과로 처리한다.

### E. 운영 전 검증

실제 정보 반입·기관 인증·법령·보존기간·악성파일 검사·공공 클라우드/망연계 여부는 기관 확인사항이다. 이것을 코드만으로 확보했다고 표현하지 않는다. 현재 테스트는 합성 데이터 기반 Linux Chromium 중심이며 Mac/Windows 실제 브라우저, Docker, 실제 기관망은 로컬 검수 대상이다.
