# Codex 최종 인계 · 파일 등록 / 조달청 / AI 대화창

2026-11-04. v0.7 구현 커밋 `80a74466edb3ff987acc6374810cfd090bca2ad7`에 이어 v0.7.1 보완. 사용자의 기존 Codex 환경에는 **AI 및 조달청 키가 이미 설정되어 있다.** 키를 다시 요청하거나 이 대화/Git에 올리지 않는다.

## 완료된 프로그램 범위

엑셀(XLSX/XLS)·OZD 공통 등록, 드래그 업로드, 원본 BLOB/해시 보존, 소요조회 품명/번호/수량/취득단가/원본 상태 표시, 등록 후 조달청 조회 및 정확번호 후보 빈칸 입력, 부서/묶음/사진/이력, 일반 대화형 RAG UI와 접힌 참고자료 패널. 기존 승인·기관격리·수량예약·대장 확인은 유지한다.

OZD는 전용 변환기 연동 코드와 원본 보관·대기·수동 변환 XLSX 연결 기능까지 구현됐다. 실제 OZD 해석 엔진은 포함되지 않았다. `tools/ozd-bridge`는 내부 통신 래퍼이며 조달청 API나 OZ 제품의 공식 API가 아니다. 엔진/라이선스 없이 자동변환을 완료했다고 표시하지 않는다.

v0.7.1: 변환 대기 OZD를 하루 후에도 재개하며, 변환 성공 시점부터 미리보기24시간을 계산한다. 업로드일/원본은 변경하지 않는다. 변환 전 원본 SHA-256을 다시 검사하고 손상된 원본은 전송·수동 연결을 차단한다. AI의 Markdown 출처 링크도 본문에 잔여주소 없이 숨긴다. 서버 인용ID 검증은 유지한다. 추가 DB 스키마 변경은 없다(v0.7 schema4 그대로).

## 병렬 에이전트 분담

Codex에서 서브에이전트 실행을 지원하면 아래 세 역할을 실제로 실행하라. 지원하지 않으면 에이전트를 실행한 것처럼 보고하지 말고 동일 범위로 순차 검수한다.

- **A / 입력·OZD:** `server/document-import.mjs`, `server/ozd-converter.mjs`, `server/import-lifecycle.mjs`, `tools/ozd-bridge/`를 담당한다. 사용자 실제 파일은 로컬에서만 열어 품명·번호·수량·폐품·취득단가를 대조한다. 허가된 OZ 엔진 및 실제 내보내기를 연결·검증한다. 프런트엔드나 공통 DB 스키마는 임의로 변경하지 않는다.
- **B / 화면·대화:** `src/components/DropArea.tsx`, `src/features/ExcelImport.tsx`, `src/pages/Assistant.tsx`, `shared/chat-text.mjs`, 관련 CSS를 담당한다. 드래그/다중파일 오류/한글IME/Enter·Shift+Enter/출처 기본접힘/재시도·중단/데스크톱·390px 모바일를 검수한다. API키와 서버 보안규칙은 변경하지 않는다.
- **C / 통합·보안 검수:** read-only로 기존 API환경 설정 여부, 실제 조달 1건 조회, DeepSeek 공개 안내 실응답, 권한·원본·회귀검사를 확인한다. 전체 비밀파일/키/키가 들어간 URL/compose 설정 전체를 출력하지 않는다. A·B 파일을 중복 수정하지 말고 이슈를 통합 담당에게 전달한다.

통합 담당만 공통 파일·lockfile·버전·배포를 변경한다. 테스트별 포트/데이터 경로/아티팩트 경로를 나누며, **전체 Playwright는 한 번에 하나만 실행**한다. 먼저 A/B/C 결과를 합친 후 최종 전체검사·커밋·배포를 수행한다.

## 실행 지시

1. 최신 main과 작업 트리·현재 NAS 배포 버전을 확인한다. `AGENTS.md`, `docs/V07_DOCUMENT_IMPORT_CHAT.md`, `docs/CODEX_V07_HANDOFF.md`, 이 문서, `docs/NAS_DEPLOYMENT.md`, `tools/ozd-bridge/README.md`를 읽는다. 미커밋 변경은 보존하고 ff-only 갱신한다. DB·uploads·계정·RAG corpus·Cloudflare·HTTPS·네트워크·다른 앱을 초기화/삭제/덮어쓰지 않는다.
2. 기존 `.env`, `.env.nas`, 운영 비밀설정의 **사용 경로와 설정 존재 여부만** 확인한다. `DATA_GO_KR_SERVICE_KEY`/`PROCUREMENT_*`, `DEEPSEEK_API_KEY`/`RAG_MODEL`/`RAG_*`를 재사용한다. 기존 모델ID·공급자·사진AI·카카오 설정을 바꾸지 않는다. 키를 출력하거나 재발급하지 않는다.
3. `npm ci`, `npm test`, `npm run build`, `npm run test:e2e`를 실행한다. 실제 사용자 XLSX는 소요조회 물품목록 원본 값과 결과를 대조한다. 드래그→미리보기→초안→조달청 실조회→선택/정확번호 빈칸 입력→상세페이지를 확인한다. 조회 실패/없는 번호도 초안을 보존해야 한다. ‘폐품’은 원본값으로 유지하고 실사 전 양호/공개로 바꾸지 않는다.
4. OZD 전용 변환 엔진과 라이선스, 정식 내보내기 경로가 있으면 브릿지에 연결한다. 존재하지 않는 CLI옵션·ProgID를 만들거나 임의 바이너리를 설치하지 않는다. 전용 저권한 계정·비공개 통신·별도 토큰을 사용한다. 실제 OZD→변환표→원문번호/수량 검증 후 켠다. 엔진이 없으면 그 제한을 명시하고 엑셀·채팅 작업은 계속 마무리한다. 원본보관/대기 및 같은 OZD의 수동 XLSX 연결은 유지한다.
5. 기존 DeepSeek 설정으로 공개 프로그램 안내부터 실응답을 확인한다. 허용된 지침만 외부 전송한다. 본문의 `[S1] 출처 보기`류 표시가 없고, 참고자료 버튼을 누를 때만 출처가 열려야 한다. 읽기 권한·근거ID 검사를 삭제하지 않는다. RAG는 업무 승인·장부 수정 권한이 없다.
6. 일관된 기존 DB·파일 백업과 별도 경로 복원 검증 후 NAS 서비스를 업데이트한다. 실제 버전이 v0.6 이하면 v0.7 schema4 추가 마이그레이션이 필요하다. 최신v0.7.1은 추가 마이그레이션 없음. `rag-usage.sqlite`와 corpus도 따로 보존한다. `down -v`, `prune`, `reset --hard`, DB초기화 금지. 실패하면 현재 DB는 보존하고 이전 코드/백업을 새 경로에서 복원한다.
7. 변경 코드를 커밋·푸시한 뒤 실제 배포SHA, 실행주소, 테스트, 조달청 실조회, AI 실모델/실응답, OZD 실제 엔진 여부와 미완료 사항을 각각 보고한다. 서버 키나 기관 원본 데이터는 보고서/Git에 포함하지 않는다.
