# 시연과 검수

## 합성 데이터

가상 기관 3개, 담당자/검토자 6명과 운영관리자 1명, 물품 묶음 6개를 만든다. 의자는 80개 중 양호 50·사용감 20·수리검토 10이다. 타 기관에는 공유 가능한 70개만 노출된다. 원본 대장은 한 자산행에 전체 수량이 있는 예로 구성하여 대량 물품 처리 방식을 보여 준다. 제품 그림과 결정 증빙은 합성물이다.

## 5분 기능 설명 흐름

1. 사진형 목록에서 의자 검색 → 상태별 수량과 운반 조건 확인.
2. 다른 기관의 담당자로 3개 신청 → 보내는 담당자가 예비 배정.
3. 검토자 계정을 구분해 양 기관 합의·승인 기록. 근거 없는 단순 체크가 아닌 증빙 파일+처리번호 연결.
4. 연결된 자산행에서 이번 인계 수량 3개만 선택.
5. 3개 인계 후 2개 인수 입력 → 불일치와 수량 보류 확인. 실제 나머지 1개를 확인한 상황을 가정해 3개 인수로 정정.
6. 양 기관 대장 반영 확인 후 ‘증빙 확인 완료’. 화면의 API 미연결 표시 확인.

실제 공식 승인을 시연하는 것이 아니므로 테스트 PDF/이미지에 ‘합성 시연 증빙’이라고 명시한다. 새 물품 게시 시연은 사진·불용 근거를 모두 붙인 뒤 작성자와 다른 검토자 계정으로 승인한다.

## 자동 테스트

- 도메인: 비공개 접근, 작성자 승인 금지, 다른 기관 승인 금지, 필수 증빙, 운영관리자 역할 분리, 원본 보존, 상태 수량 검증, 멱등 요청, 자기 기관 신청 금지, 예약·취소, 자산원본/배분, 선행 승인, 인계·불일치·완료, 정보삭제, 결정 취소, 증빙 접근, 온비드 중복 처리 방지, 감사 불변, CSV 수식 방지, 외부 미연결.
- 실제 동시성: 독립 Worker/SQLite 연결 두 개가 같은 그룹을 동시에 예약. 합계 초과 방지 확인.
- HTTP: 인증/Origin/CSRF, 세션 쿠키 속성, 실제 이미지 업로드·재인코딩, 비공개 첨부 차단, 역할별 접근.
- 브라우저: 로그인, 카드 검색, 상세, 신청·재조회, 초안 저장·새로고침, 모바일 390px 폭과 메뉴, 관리자 화면.
- 후속 로컬 검수: 신규 등록부터 양 기관 대장 확인까지 실제 UI 전체 흐름, UTF-8/CP949 파일, CSV/ZIP 실제 다운로드, 한글 증빙 헤더, 부분 첨부 실패, HEIC 재선택, 저장 버전 충돌, 새 경로 백업복원을 추가했다. 결과는 [TEST_REPORT.md](TEST_REPORT.md)에 있다. E2E는 4311과 실행별 새 DB를 사용하며 시연 서버를 재사용하지 않는다.

현재 커밋의 결과는 GitHub Actions가 기준이다. 실패한 테스트를 건너뛰거나 수용 기준을 낮춰 성공처럼 보고하지 않는다. 시각 검수는 자동 폭 검사만으로 대체되지 않으며, Codex에서 생성 스크린샷과 실제 화면을 직접 확인한다.

## 수동 검수 체크

- 1440px 데스크톱 / 390px 모바일에서 제목·버튼·표가 잘리지 않는가?
- 실제 스마트폰 사진(8MB 이하 JPG/PNG/WebP) 업로드가 동작하는가?
- iPhone 기본 HEIC은 현재 직접 지원하지 않으므로 JPEG 변환 또는 호환 카메라 설정 안내가 필요한가?
- 실제 CSV의 열 이름·숫자·앞자리 0·한글 인코딩이 정확한가?
- 승인 버튼을 누르기 전 첨부 증빙을 확인하는 사용자 흐름이 이해되는가?
- 인수 불일치를 확인하면 재고로 반환되지 않는가?
- 업무용 계정은 비밀번호를 바꾸고 데모 계정/자료와 분리했는가?
- 공식 완료로 오해할 수 있는 화면 문구가 없는가?
